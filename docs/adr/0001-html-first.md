# ADR-0001：受限 HTML 契约前置为阶段一主线

- 状态：已接受
- 日期：2026-10-24

## 背景

原总体方案把「受限 HTML 模式」列为 V2，需先通过门禁（LLM 一次通过率、映射覆盖率、token
经济性、工作量）才投入实现。当时的主要顾虑是：自由 HTML→PPTX 有损，审核物与交付物不一致。

但原方案的 native 主线有一个更长的关键路径：10 种版式与双尺寸模板必须由设计在 PowerPoint
里人工制作，且这套资产的质量直接决定成品「能不能看」。相比之下，转换核心（白名单校验、
auto-fix、DOM 序映射、DrawingML 直写）已经在最小验证代码里跑通，包含渐变、阴影、圆角语义、
精确行距、表格与图片 contain 落位，落位回读偏差为 0。

## 决定

1. 阶段一交付**受限 HTML 契约 v1 + HTML→PPTX 转换器**，以独立可安装的库 + CLI 形式存在。
2. MCP 协议层后置到阶段二；转换器任何时候不依赖 `mcp` / `fastmcp`。
3. 门禁指标不取消，只**顺延并换口径**：保真度先用「声明 px → EMU 回读」衡量；LLM 一次
   通过率与 token 经济性在 MCP 层可用后实测。

## 后果

- 原方案 §10 中「V1 交付后再评审是否投入」的表述不再适用，以本 ADR 为准；§10.3/§10.4 的
  「白名单即映射表」「表外一律报错」原则继续有效。
- 交付物首先是 `ppt-mcp-server` 包里的 `ppt_mcp.convert` 子系统，脱离 MCP 也能使用。
- 如果后续实测不达标，可以退回 native 主线，转换器降级为可选前端，已投入的工作不会作废。
- 模板资产与主题系统仍在路线图上，只是不再阻塞第一阶段的产出。
